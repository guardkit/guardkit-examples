# Task: Configure Alembic migrations and create users table

## Description

Set up Alembic for async database migration management and create the initial migration for the users table. Follow the project template patterns for Alembic configuration including proper logger sections.

## Scope

### Files to Create
- `alembic.ini` - Alembic configuration with all required logger sections
- `alembic/env.py` - Async migration environment using project engine
- `alembic/script.py.mako` - Migration template
- `alembic/versions/` - Directory for migration files
- Initial migration file for `users` table

### Files to Modify
- None (uses infrastructure from TASK-DB-001)

## Technical Requirements

### Alembic Configuration
- Use async engine from `src/db/session.py`
- Configure `target_metadata` from Base.metadata
- Include all logger sections (root, sqlalchemy, alembic) to avoid ValueError
- Date-prefixed migration file naming
- Post-write hooks for ruff formatting (if ruff installed)

### Async env.py
- Use `run_async_migrations()` pattern with `connectable.connect()`
- Import all models before autogenerate (import `src.db.base` and all feature models)
- Configure `compare_type=True` for detecting column type changes

### Initial Migration
- Generate via `alembic revision --autogenerate -m "create users table"`
- Users table with: id, email, username, hashed_password, full_name, is_active, is_superuser, created_at, updated_at
- Indexes on email and username (unique)
- Review autogenerated migration before applying

## Acceptance Criteria
- [ ] `alembic revision --autogenerate` generates migration files
- [ ] `alembic upgrade head` applies migrations to PostgreSQL
- [ ] `alembic downgrade -1` rolls back cleanly
- [ ] Users table created with correct schema and indexes
- [ ] No logger ValueError in alembic.ini configuration
- [ ] Migration history tracked correctly

## Testing Notes
- Standard testing depth
- Verify migration applies and rolls back cleanly
- Verify table schema matches model definition
